# Gaussian processes for vol surfaces and curves

Most ML methods need lots of data; Gaussian processes (GPs) work beautifully with little. They give you a fitted *function* through your data points with calibrated uncertainty at every input. For vol surface fitting, interest-rate curves, and any task where the input space is low-dimensional and the data is sparse but precious, GPs are often the right tool.

## The picture

A Gaussian process places a prior distribution over functions. Given some data points, the posterior is also a Gaussian process — you can compute the mean and variance at any new input in closed form. The variance grows in regions far from training data, which is what gives GPs their honest uncertainty.

Two ingredients:

- **Mean function** $\mu(x)$ — usually zero; the GP models deviations from it.
- **Kernel** $k(x, x')$ — the covariance function. Encodes how "close" two inputs are. Standard choices: RBF (Gaussian, smooth), Matérn (controllable smoothness), Rational Quadratic (mixed scales).

For an observation $y$ at input $x$ with noise $\sigma_n^2$, the GP posterior at a new $x^*$ is:

$$
\mathcal{N}\!\left( \mu^* = k_*^\top (K + \sigma_n^2 I)^{-1} y,\; (\sigma^*)^2 = k(x^*, x^*) - k_*^\top (K + \sigma_n^2 I)^{-1} k_* \right)
$$

where $K$ is the kernel matrix on training points and $k_*$ is the vector of kernels between training points and $x^*$.

## A working example with scikit-learn

```python
import numpy as np
from sklearn.gaussian_process import GaussianProcessRegressor
from sklearn.gaussian_process.kernels import RBF, ConstantKernel, WhiteKernel

# Sparse vol surface: a few strikes and a few expiries with observed IVs
strikes = np.array([0.85, 0.9, 0.95, 1.0, 1.05, 1.1, 1.15])      # in moneyness
expiries = np.array([7, 30, 60, 90, 180])                          # in days

# Pretend we have observations
X = np.array([[k, t] for k in strikes for t in expiries])
y_iv = some_observed_iv_function(X)

kernel = ConstantKernel(1.0) * RBF(length_scale=[0.1, 30]) + WhiteKernel(0.01)
gp = GaussianProcessRegressor(kernel=kernel, normalize_y=True, n_restarts_optimizer=5)
gp.fit(X, y_iv)

# Predict on a dense grid
K_grid, T_grid = np.meshgrid(np.linspace(0.8, 1.2, 60), np.linspace(5, 200, 60))
X_test = np.column_stack([K_grid.ravel(), T_grid.ravel()])
mu, sigma = gp.predict(X_test, return_std=True)
```

`mu.reshape(K_grid.shape)` is your smooth, continuous vol surface estimate. `sigma.reshape(K_grid.shape)` is the GP's pointwise uncertainty — naturally smaller near training points, larger far from them.

## Kernel choice matters

For vol surfaces:

- **RBF (infinitely smooth)** — usually too smooth; real surfaces have kinks near ATM.
- **Matérn-2.5** — twice differentiable; better default.
- **Anisotropic length scales** — different scales for moneyness and time; essential when the inputs have different units.

For interest-rate curves:

- **Matérn-3/2 or Matérn-5/2** — captures the kinks in real yield curves better than RBF.
- **Periodic kernels** (`ExpSineSquared`) — when the curve has known cyclical structure (rare for rates).

Test a few and check held-out log-likelihood:

## A worked example: smoothing a sparse vol surface

```python
import numpy as np
from sklearn.gaussian_process import GaussianProcessRegressor
from sklearn.gaussian_process.kernels import Matern, ConstantKernel, WhiteKernel

# 30 observed quotes: (log_moneyness, days_to_expiry, implied_vol)
np.random.seed(0)
rng = np.random.default_rng(0)
log_m = rng.uniform(-0.2, 0.2, 30)
dte = rng.integers(7, 180, 30)
# True surface: SVI-like shape + noise
true_iv = 0.15 + 0.1 * log_m ** 2 - 0.02 * log_m + 0.0001 * dte
obs_iv = true_iv + rng.normal(0, 0.005, 30)

X = np.column_stack([log_m, dte])
kernel = ConstantKernel(0.01) * Matern(length_scale=[0.05, 30], nu=2.5) + WhiteKernel(0.005)
gp = GaussianProcessRegressor(kernel=kernel, normalize_y=True, n_restarts_optimizer=5).fit(X, obs_iv)

# Smooth surface
lm, dt = np.linspace(-0.3, 0.3, 40), np.linspace(5, 200, 40)
LM, DT = np.meshgrid(lm, dt)
mu, sigma = gp.predict(np.column_stack([LM.ravel(), DT.ravel()]), return_std=True)
mu, sigma = mu.reshape(LM.shape), sigma.reshape(LM.shape)
```

`mu` is the fitted smooth surface; `sigma` is the GP's pointwise uncertainty. For "where is my smile mispriced?" — flag points where the *observation* is more than 2 GP-sigmas from the GP's mean.

Modules 14-15 (Options) take this much further with SVI / SSVI parameterisations that respect no-arbitrage. The GP version is a great quick-and-dirty smoother.

## GP regression with PyTorch — for bigger data

scikit-learn's GP is O(n³) in training points. For more than ~1000 points, use [`gpytorch`](https://gpytorch.ai/) which supports approximate methods that scale better:

```python
import torch
import gpytorch

class ExactGP(gpytorch.models.ExactGP):
    def __init__(self, train_x, train_y, likelihood):
        super().__init__(train_x, train_y, likelihood)
        self.mean_module = gpytorch.means.ConstantMean()
        self.covar_module = gpytorch.kernels.ScaleKernel(
            gpytorch.kernels.MaternKernel(nu=2.5, ard_num_dims=2)
        )

    def forward(self, x):
        return gpytorch.distributions.MultivariateNormal(
            self.mean_module(x), self.covar_module(x)
        )

likelihood = gpytorch.likelihoods.GaussianLikelihood()
model = ExactGP(train_x, train_y, likelihood)
```

For >10k training points, switch to [`SVGP`](https://docs.gpytorch.ai/en/latest/examples/04_Variational_and_Approximate_GPs/SVGP_Regression_CUDA.html) (stochastic variational GP) — scales to millions of points with inducing-point approximation.

## Where GPs shine in finance

- **Vol surface fitting** (sparse, smooth, calibrated uncertainty).
- **Interest rate / credit spread term structures**.
- **Implied volatility on illiquid options** — interpolate from neighbouring liquid quotes.
- **Bayesian optimisation** of strategy hyperparameters — Optuna's TPE is a kind of tree-based GP variant.

Where GPs don't:

- **High-dimensional inputs** (>10-20 features) — the kernel becomes uninformative.
- **Large datasets** without sparse approximations.
- **Strongly non-stationary functions** — RBF / Matérn assume the function's smoothness is constant.

## Pitfalls

!!! warning "Length scale optimisation can find local minima"
    Use `n_restarts_optimizer >= 5`. Otherwise you can land on a flat-prior-bad-fit local solution.

!!! warning "WhiteKernel learns the noise — but only roughly"
    For known-noise observations, fix the WhiteKernel scale rather than letting it be free.

!!! warning "GPs interpolate, they don't extrapolate"
    A GP's mean reverts to the prior far from data. Don't extrapolate vol surfaces past your observed strike range without an explicit parameterisation that respects no-arbitrage.

!!! warning "Sklearn's GP is slow"
    For >500 training points, switch to `gpytorch`. The scaling difference is dramatic.

## Bottom line

GPs are an under-used tool in retail quant. They're the right answer when:

- The input space is low-dimensional (1-5D).
- The data is sparse but precious.
- You need calibrated uncertainty, not just point estimates.

For vol surfaces specifically, a GP is the fastest path from "30 noisy quotes" to "a smooth, uncertainty-aware surface".
